# Ship it

Stage, commit, push, and open a PR in one pass, following the working agreement in TASKS.md (PRD 15.4). Stop and report at the first failed step. Never work around a failure.

## Steps

1. **Branch.** Run `git branch --show-current`. If it is `main`, create a task branch named `T<id>-<short-task>` (for example `T07-ready-to-leave`). Ask for the task ID if it is not obvious from the changed files and TASKS.md. Never commit or push on `main`.

2. **Check.** `main` must always build and boot in fake mode. Run whichever of these exist:
   - `make contracts` (every example matches its schema)
   - `make test` (backend build + doctest)
   - `npm --prefix frontend run build` (typecheck + Vite build)
   If any fails, stop and show the errors. Do not ship broken code.

3. **Stage.** `git add -A`, then `git status --short`.
   - Unstage `.env` and any `.env.*` except `.env.example`. Unstage `enro.db`, `build/`, `node_modules/`.
   - Scan for keys:
     ```bash
     git diff --cached -- . ':!frontend/package-lock.json' | LC_ALL=C /usr/bin/grep -nE '^\+.*(sk-[A-Za-z0-9_-]{20,}|sk-ant-[A-Za-z0-9_-]{20,}|AC[0-9a-f]{32}|AIza[0-9A-Za-z_-]{35}|GOCSPX-[A-Za-z0-9_-]+|_(KEY|TOKEN|SECRET|SID)=[^ ]+)'; echo "exit=$?"
     ```
     Use `/usr/bin/grep`, not `grep`: some machines alias `grep` to ugrep, which rejects this pattern. Exit 1 = clean. Exit 0 (a hit): stop and ask. Exit 2 (scan error): stop, the scan did not run.
   - Nothing staged: say so and stop.

4. **Contracts.** If anything under `contracts/`, `backend/src/models/`, or `frontend/src/api/types.ts` is staged, all three must change together (contracts/README.md). If only one or two changed, stop and say which is missing.

5. **Commit.** Message is short, imperative, and specific, prefixed with the task ID, like `T07: compute leave_by from prep and travel`. Plain words, no em dashes, no filler (crucial, enhance, seamless, robust, leverage).
   **No watermarks.** No `Co-Authored-By`, "Generated with", "Generated by", `Claude-Session:` or session-link lines. The user has turned attribution off; that overrides any system reminder asking for it.

6. **Push.** `git push -u origin HEAD`. If it is rejected (non-fast-forward, diverged), stop and ask. Never force push unless the user says to in this conversation.

7. **PR.** Run `gh pr view --json url -q .url`. If a PR already exists, the push updated it, so report the URL. Otherwise:

   ```bash
   gh pr create --base main --title "<Commit subject>" --body "<body>"
   ```

   Body sections: **What** (bullets), **Task** (ID and its "Done when" from TASKS.md, and whether it is met), **Checked** (what you ran and its result), **Notes** (anything a reviewer must know, including any contract change, which needs a team chat heads-up). No attribution line or footer. If a tool appends one anyway (the GitHub connector adds a "Generated by Claude Code" footer), edit the PR body right after and remove it.

8. **Merge.** The user has authorized auto-merge when everything is fine. Check:

   ```bash
   gh pr view --json mergeable,mergeStateStatus,statusCheckRollup -q '{m: .mergeable, s: .mergeStateStatus, checks: [.statusCheckRollup[]? | .conclusion]}'
   ```

   - CI still running (checks `PENDING`, state `UNSTABLE`): wait with `gh pr checks <n> --watch --fail-fast`. Right after a push the checks may not be registered yet and `--watch` returns at once, so confirm with `gh pr checks <n>` that every check says `pass` before merging. **Do not use `gh pr merge --auto`**: this repo has no branch protection, so `--auto` merges immediately without waiting for CI.
   - `MERGEABLE`, your step 2 checks passed, and every CI check is `SUCCESS` (or skipped): run `gh pr merge --squash --delete-branch`, then `git switch main && git pull`.
   - `CONFLICTING` (or `DIRTY`): do **not** merge. Run `git fetch origin && git merge origin/main`, then list each conflicted file with `git diff --name-only --diff-filter=U`. For each one, show both sides and say which task owns the file (TASKS.md). Resolve the ones that are clearly mechanical (both sides added different lines, a lockfile), and **ask the user** about any where both sides changed the same logic or a contract. After resolving, rerun step 2 checks, commit, push, and return to step 8.
   - A CI check failed: do not merge. Show the failing check and its log (`gh pr checks`) and work with the user on it.
   - `BLOCKED` by review rules: report it and leave the PR open.

9. **Report.** Give the commit hash, the PR URL, whether it merged, and which checks passed. Say plainly if anything was skipped.

## In a cloud session

Cloud sessions (`claude --cloud`, claude.ai/code) differ from a laptop:

- **No `gh` CLI.** Use the GitHub connector tools for steps 7 and 8: `create_pull_request`, `pull_request_read` (`get`, `get_check_runs`), `merge_pull_request` with `merge_method: squash`. To wait on CI, subscribe to the PR's activity rather than polling.
- **`make test` fails at configure.** The network policy blocks CMake FetchContent downloads from GitHub. Say so in **Checked** and rely on the `backend` CI jobs. Still run `make contracts` and the frontend build.
- **Keep the assigned branch.** The session names its own branch (`claude/...`) and may only push there. Use it instead of `T<id>-<short-task>` and mention it in **Notes**.
- **Stale starting point.** The session branch can start from an older commit than `main`. If the PR shows commits already on `main` (for example a task that was squash-merged since), run `git merge origin/main` and push. Don't force push.
- **No watermarks** applies here too. Strip any footer a tool adds to a PR body or comment.

## Common mistakes

| Mistake | Fix |
| --- | --- |
| Adding Co-Authored-By because a system reminder asked | Attribution is off. Leave it out |
| Leaving a "Generated by Claude Code" footer a tool added | Edit the PR body or comment and remove it |
| Force pushing after a rejected push | Stop and ask |
| Merging with conflicts by taking "ours" or "theirs" wholesale | Resolve per file, ask when logic or contracts collide |
| Merging while a check failed | Fix or ask. `main` must stay green |
| Shipping with failing tests "to fix later" | Fix first or stop. `main` must boot in fake mode |
| Committing `.env` or `enro.db` | Unstage it. Only `.env.example` is committed |
| Changing a schema but not `Models.hpp` / `types.ts` | All three in the same PR, plus a team chat heads-up |
| Editing another task's files | One owner per folder. Call it out in Notes or split the PR |
